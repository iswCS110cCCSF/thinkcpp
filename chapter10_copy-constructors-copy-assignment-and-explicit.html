    Section 10.5 Copy Constructors and Copy Assignment

    When a class object is copied, C++ must decide how to initialize or update the destination object. Two operations are especially important: a copy constructor creates a new object from an existing object, while a copy-assignment operation updates an object that already exists.
    🔗
    C++ can generate ordinary memberwise copying automatically. That default behavior is useful for many classes, but it can be unsafe when a class owns a raw pointer. We will first learn the two copying operations and then see why resource-owning classes need special care.
    🔗

    Subsection 10.5.1 The Copy Constructor

    A copy constructor is a constructor whose parameter is a reference to an object of the same class. The usual form is:
    🔗
    class Score {
public:
    Score(const Score& other) {
        // Copy the state from other.
    }
};
    The ampersand means that other is received by reference, so C++ does not make another copy just to pass the source object into the copy constructor. Without the ampersand, passing a Score by value would require another copy and could cause the copy constructor to call itself repeatedly. The const keyword allows the constructor to copy from a read-only source and promises that it will not modify that source. A copy constructor is used when a new object is initialized from an existing object.
    🔗
    Score copied{original}; creates a new object, so it uses the copy constructor. The statement assigned = original; changes an object that was already created, so it uses copy assignment. The compiler can provide a memberwise copy-assignment operation even when we do not write one ourselves.
    🔗
    🔗

    Subsection 10.5.2 Copy Assignment Updates an Existing Object

    The assignment statement does not call a constructor for the destination. The destination was already initialized. It instead copies the source object’s current state into the existing object. The assignment syntax will be studied more broadly with operator overloading later in this chapter.
    🔗
    🔗

    Subsection 10.5.3 explicit and Copy Initialization

    The explicit keyword prevents a constructor with one argument from being used for an unintended implicit conversion. It does not prevent ordinary copying of an object from another object of the same type.
    🔗
    The expression Score copied = original; initializes a new Score from an existing Score, so the copy constructor is appropriate. The commented statement would ask C++ to convert an int into a Score implicitly, which the explicit constructor prevents.
    🔗
    🔗

    Subsection 10.5.4 Memberwise Copying and Raw Pointer Risk

    The compiler-generated copy operations copy each data member. For ordinary values such as integers and strings, this is often exactly what we want. For a raw pointer, however, memberwise copying copies the address rather than the dynamically allocated object.
    🔗
    class ScoreHolder {
private:
    int* score_pointer;

public:
    ScoreHolder(int starting_score)
        : score_pointer{new int{starting_score}} {
    }

    ~ScoreHolder() {
        delete score_pointer;
    }
};

// A compiler-generated copy can make two objects contain
// the same score_pointer address.
    If two objects contain the same owning pointer, both destructors may try to release the same allocation. This can cause undefined behavior. This address-only duplication is called a shallow copy: the pointer value is copied, but the dynamically allocated object is not duplicated. A deep copy would allocate separate storage for the second object and copy the pointed-to value into that new storage.
    🔗
    A class that owns a raw resource commonly needs a destructor, a copy constructor, and a copy-assignment operation that coordinate with one another. This is the Rule of Three, which we will develop fully in Pointers and Dynamic Memory, Part 2.
    🔗
    🔗

    The visualization steps through creation of an original object and a copied object to show how data is replicated in memory. The two objects contain equal values, but they are separate objects.

    Checkpoint 10.5.4.

    What is the difference between Score copy{original}; and copy = original;?
    🔗
    • The first creates a new object; the second updates an existing object.
    • Copy construction begins a new lifetime, while assignment changes an existing object.
    • They always call exactly the same constructor.
    • Assignment does not construct the already existing destination.
    • The first changes the original; the second creates a new object.
    • The destination of each expression determines the operation.
    • The first works only for pointers; the second works only for structures.
    • Both operations can apply to user-defined class objects.
    🔗

    Checkpoint 10.5.5.

    Which declaration has the usual form of a copy constructor for Score?
    🔗
    • Score(const Score& other);
    • A copy constructor receives a const reference to an object of the same class.
    • Score(int other);
    • This is a converting or ordinary value constructor, not a copy constructor.
    • void Score(Score other);
    • Constructors have no return type, and passing by value would require another copy.
    • Score* Score(const Score& other);
    • A constructor does not declare a return type or return a pointer.
    🔗

    Checkpoint 10.5.6.

    Arrange the statements to demonstrate copy construction followed by copy assignment.
    🔗
    Score original{90};
---
Score copied{original};
---
Score assigned{0};
---
assigned = original;
    🔗

    Checkpoint 10.5.7.

    What does explicit Score(int starting_value) prevent?
    🔗
    • Implicit conversion of an int into a Score
    • explicit requires direct initialization such as Score score{90};.
    • Copying one Score object into another
    • Ordinary copying between Score objects remains allowed.
    • Calling every member function
    • explicit affects constructor conversions, not member-function calls.
    • Creating a Score with braces
    • Direct-list initialization with braces is permitted.
    🔗

    Checkpoint 10.5.8.

    Why can compiler-generated memberwise copying be dangerous for a class that owns a raw pointer?
    🔗
    • It can copy the address, causing two objects to release the same allocation.
    • Copying a pointer value does not copy the dynamically allocated object.
    • It always changes the pointer into a reference.
    • Memberwise copying preserves the pointer type and copies its address value.
    • It prevents the destructor from running.
    • The destructor still runs, which is part of the danger when ownership is duplicated.
    • It automatically converts the raw pointer to a smart pointer.
    • Compiler-generated copying does not change the pointer type.
    🔗
