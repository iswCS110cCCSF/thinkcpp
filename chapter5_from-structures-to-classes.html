    Section 5.4 From Structures to Classes

    In the previous sections, you used struct to group related data and behavior into one type.
    🔗
    struct Rectangle {
    double length;
    double width;

    double calculate_area() const;
    void double_size();
};
    C++ also provides another user-defined type called a class. A class can also contain data members and member functions.
    🔗
    In fact, struct and class are very closely related in C++. One important difference is the default access given to their members.
    🔗

    Subsection 5.4.1 Classes and Objects

    A class is a user-defined type that describes a category of objects. The class specifies the data those objects contain and the operations they can perform.
    🔗
    A useful analogy is to think of a class as a blueprint. The blueprint describes how objects of that class are organized, while each object is a separate instance created from that description.
    🔗
    For example, a Rectangle class can describe the data and behavior shared by all rectangle objects:
    🔗
    class Rectangle {
public:
    double length;
    double width;

    double calculate_area() const;
};
    We can then create different objects of the same class:
    🔗
    Rectangle room{12.0, 8.0};
Rectangle table{6.0, 3.0};
    Both room and table are objects of the Rectangle class. They have the same kinds of data and behavior, but each object has its own state.
    🔗
    An object created from a class is also called an instance of that class.
    🔗
    The class describes what all objects of that type have in common; each object stores its own values for its data members.
    🔗
    🔗

    Subsection 5.4.2 A Struct and a Class Can Look Very Similar

    Consider the familiar Rectangle structure:
    🔗
    struct Rectangle {
    double length;
    double width;

    double calculate_area() const;
};
    We can write a very similar type using class:
    🔗
    class Rectangle {
public:
    double length;
    double width;

    double calculate_area() const;
};
    The keyword public means that code outside the class may access these members.
    🔗
    With public: written explicitly, this class can be used in much the same way as the earlier structure:
    🔗
    Rectangle room{12.0, 8.0};

std::cout << room.length << '\n';
std::cout << room.calculate_area() << '\n';
    Both struct and class can therefore contain:
    🔗
    • data members
      🔗
      🔗
    • member functions
      🔗
      🔗
    🔗

    Subsection 5.4.3 Default Access

    The main difference we need to know right now is the default access of members.
    🔗
    Members of a struct are public by default.
    🔗
    struct Rectangle {
    double length;
    double width;
};
    This means that code outside the structure may access the members:
    🔗
    Rectangle room{12.0, 8.0};

room.length = 15.0;
room.width = 10.0;
    Members of a class, however, are private by default.
    🔗
    class Rectangle {
    double length;
    double width;
};
    In this version, code outside the class cannot directly access length or width.
    🔗
    Rectangle room;

room.length = 15.0;   // error
    We will study public and private members in more detail in the next section.
    🔗
    🔗

    Subsection 5.4.4 Making Class Members Public

    If we want class members to be accessible from outside the class, we can use the public: access label.
    🔗
    class Rectangle {
public:
    double length;
    double width;
};
    Now the data members can be accessed using the dot operator:
    🔗
    Rectangle room{12.0, 8.0};

room.length = 15.0;
room.width = 10.0;
    The public: label applies to the members that follow it until another access label appears or the class definition ends.
    🔗
    For example:
    🔗
    class Rectangle {
public:
    double length;
    double width;

    double calculate_area() const;
};
    Here, both data members and the member function are public.
    🔗
    🔗

    Subsection 5.4.5 Why Use a Class?

    If structures can already contain both data and member functions, why would we use a class?
    🔗
    One important reason is that a class can control how code outside the class accesses and changes its data.
    🔗
    Consider a rectangle whose dimensions should never be negative. If the data members are public, any part of the program can write:
    🔗
    room.length = -5.0;
    The object now contains a value that may not make sense for the problem being modeled.
    🔗
    A class can hide some data from outside code and provide member functions that control how the object’s state is changed.
    🔗
    This idea is called encapsulation. We will begin exploring it in the next section.
    🔗
    🔗

    Subsection 5.4.6 struct or class?

    In C++, both struct and class are capable of representing objects with state and behavior.
    🔗
    A useful beginner guideline is:
    🔗
    • Use a struct when the type is primarily a simple collection of related data and direct access to that data is appropriate.
      🔗
      🔗
    • Use a class when the type should control access to its internal state and provide a public interface for using the object.
      🔗
      🔗
    These are design guidelines rather than strict language rules. C++ allows both structures and classes to contain data members and member functions.
    🔗
    🔗

    Subsection 5.4.7 Classes as Abstractions

    A class can provide more than a way to group data and functions. It can also define a clear boundary between how an object is used and how it is implemented internally.
    🔗
    Code outside the class can work through a set of public operations, while some of the object’s internal data can remain hidden.
    🔗
    This creates an abstraction: users of the class can focus on what the object can do without needing to know every detail of how it stores and manages its state.
    🔗
    Keeping data private is an important part of this design because it allows the class to control how its state is changed. In the next section, we will examine public and private members in detail.
    🔗
    🔗

    Subsection 5.4.8 Check Your Understanding

    Checkpoint 5.4.1.

    Which statement about C++ structures and classes is true?
    🔗
    • Only classes can contain member functions.
    • Both structures and classes can contain member functions.
    • Both structures and classes can contain data members and member functions.
    • In C++, both can represent objects with state and behavior.
    • Structures can contain data, while classes can contain only functions.
    • Both structures and classes can contain data and functions.
    🔗

    Checkpoint 5.4.2.

    What is the default access for members of a struct?
    🔗
    • public
    • Members of a structure are public by default.
    • private
    • Members of a class are private by default.
    • const
    • const describes whether something may be modified; it is not an access level.
    🔗

    Checkpoint 5.4.3.

    What is the default access for members of a class?
    🔗
    • public
    • Public is the default for a structure, not a class.
    • private
    • Members of a class are private by default.
    • protected
    • protected is another access level, but it is not the default for a class.
    🔗

    Checkpoint 5.4.4.

    Why might a programmer choose a class instead of exposing all data members publicly?
    🔗
    • Because structures cannot contain functions.
    • Structures can contain member functions in C++.
    • To control how outside code accesses and changes the object’s state.
    • Controlling access to internal state is an important reason for using classes.
    • Because class objects do not contain data members.
    • Classes can contain data members just like structures.
    🔗

    Checkpoint 5.4.5.

    Which type is the stronger candidate for a class according to the design guideline in this section?
    🔗
    • A Point that simply stores public x and y coordinates.
    • A small type whose purpose is primarily to group related data is often a reasonable use of a struct.
    • A Thermostat that should control how its temperature setting is changed.
    • A class is a natural choice when the type should provide operations that control access to its internal state.
    • Any type that contains at least one member function.
    • Structures can contain member functions too, so the presence of a member function alone does not require a class.
    🔗

    Checkpoint 5.4.6.

    What does it mean to say that a class provides an abstraction?
    🔗
    • Every detail of the object’s representation must be visible to code that uses it.
    • Abstraction allows users of a type to work through its interface without depending on every implementation detail.
    • Outside code can focus on what the object can do without needing to know every detail of how its state is stored.
    • The public operations describe how to use the object while implementation details can remain hidden.
    • All objects of the class share one copy of their data.
    • Each object has its own state. Abstraction concerns the boundary between how an object is used and how it is implemented.
